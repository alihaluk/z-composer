# Conformance Suite

Test cases for fillers of Z-Composer ZPL templates. A filler that passes every strict case follows the [output specification](../docs/OUTPUT_SPEC.md). The cases do not depend on any language or library: each one is a JSON file with a template, data and the expected output.

The expected outputs were written by hand from the specification, not generated by the reference filler. The reference filler (`src/lib/zplFill.ts`) runs the suite in CI (`src/lib/conformance.test.ts`).

## Case format

Each file in [`cases/`](./cases) is one case. The structure is described by [`case.schema.json`](./case.schema.json).

| Field | Meaning |
|---|---|
| `id` | Short name, unique in the suite. |
| `section` | Section of the specification the case is about. |
| `title` | What the case checks. |
| `locale` | Culture the filler formats with (section 6). |
| `strict` | Optional, default `true`. `false` marks localized date codes (`d`, `D`, `t`, `g`), whose exact text follows each platform's culture data (section 6.2). A mismatch there is a warning, not a failure. |
| `lineEnding` | Optional, `lf` (default) or `crlf`. |
| `template` | The ZPL template, one array item per line. |
| `data` | The document the template is filled with. |
| `images` | Optional. Graphic data for dynamic images by key, already converted to `^GFA` (without `^FO` and `^FS`). The filler's image source returns this value; a key that is not listed has no image (section 8). |
| `expected` | The filled output, one array item per line. |
| `error` | `true` when the filler must reject the template instead of filling it. A case has either `expected` or `error`. |

Scaling and converting images is the filler's own work, so the suite gives the converted data and checks only where it goes.

## Running the suite

For each case:

1. Join the `template` lines with LF, or with CRLF when `lineEnding` is `crlf`.
2. Fill the template with `data` in `locale`. For dynamic images, use `images` as the image source.
3. If `error` is `true`, the filler must fail (throw, return an error). Otherwise compare the output with `expected`.

Compare line by line after removing, from both sides:

- empty lines,
- lines that start with `^FX` (fillers may keep or remove marker lines, section 3).

Lines must match exactly, including spaces. Line endings in the output are not compared.

## Example runner (TypeScript)

```ts
import { readdirSync, readFileSync } from 'node:fs';

const normalize = (zpl: string) => zpl.split(/\r?\n/).filter(l => l.length > 0 && !l.startsWith('^FX'));

for (const file of readdirSync('conformance/cases')) {
  const c = JSON.parse(readFileSync(`conformance/cases/${file}`, 'utf8'));
  const template = c.template.join(c.lineEnding === 'crlf' ? '\r\n' : '\n');
  let actual: string[] | 'error';
  try { actual = normalize(myFill(template, c.data, c.locale, key => c.images?.[key] ?? null)); }
  catch { actual = 'error'; }
  const ok = c.error ? actual === 'error' : JSON.stringify(actual) === JSON.stringify(c.expected);
  if (!ok) console.log(`${c.strict === false ? 'WARN' : 'FAIL'} ${file}: ${c.title}`);
}
```

## Notes for implementers

These are the points where fillers most often differ from the specification:

- **Booleans** print as `true` / `false` in lower case (.NET `bool.ToString()` gives `True`).
- **Rounding** is half away from zero: `2.5` → `3`, `-2.5` → `-3` (.NET `Math.Round` defaults to banker's rounding).
- **Negative zero**: a value that rounds to zero prints without a minus sign (`-0.004` with `N2` → `0.00`); .NET, Java and JavaScript print `-0.00` by default.
- **Numeric strings** are only `-?digits[.digits]` with optional surrounding white space; `1e3` and `1234,5` are not numbers.
- **Dates** are printed with the clock time as written; an offset (`+03:00`, `Z`) is never converted.
- **`max`** counts Unicode code points, not UTF-16 units: `😀` is one character.
- **Escaping order**: `_` first, then `^` and `~`. Code 128 `>` and `^FB` backslashes come before that.
- **Placeholders are replaced once**: a value that contains `{{…}}` is printed as is.
- **Growing text**: only lines with a `y` greater than the growing element's `y` move; lines on the same `y` stay.
- **Length**: `^LL` is the sum of the printed band copies, at least 1.
